# 合作表单简化与保存校验验收

日期：2026-11-04。验证范围为本地源码、隔离 HTTP / 浏览器与生产构建，没有操作生产后台或真实 Shopify 店铺。

## 原因与修改

截图把 `/maya` 填成“推广落地路径”，而服务端只允许首页、商品和系列等站内购物路径，因而返回 `400 invalid_input` 和 `target` 字段详情。原页面忽略详情，仅显示“请检查表单内容”。这不是保存合作需要 Shopify 令牌；合作资料保存在本机 SQLite。

现仅填写一次“KOL 名称”，服务器自动生成固定唯一别名。英文可生成 `maya`，已有别名占用时追加随机后缀；非拉丁或不足两位的名称使用 `kol-` 系统编号。唯一索引覆盖暂停和历史记录；旧客户端显式别名仍受原有唯一性和不可修改约束。编辑名称保留别名，条款按版本记录，无需数据库迁移。

社媒主页可省略或留空，填写时仍验证 HTTPS URL；合作详情显示“未填写”。“链接打开页面”改为首页/全部商品选择，历史合法目标保留。字段错误使用中文原因，弹窗聚焦并滚动到错误处，输入内容保留，关闭后重新新增不会残留旧错误。

## 自动化证据

- 先运行新增回归：核心逻辑 3 项失败，覆盖缺省别名、可选主页和明确的目标/日期错误，再实现服务端行为。
- 回归覆盖：同名与非拉丁/长名称、暂停别名保留、改名保持旧链接、空白主页归一化、错误 URL 拒绝、无令牌真实 API 创建/修改、错误保存不产生记录、表单单名称及目的地、字段错误与焦点。
- 初次全量 `pnpm test --maxWorkers=2 --reporter=dot`：98 文件、627 测试通过。
- 补充错误自动定位后，生产构建（含先行 ESLint、Next 类型检查）通过；并行构建时一次全量复跑有 3 个既有部署脚本测试触发 5 秒超时，其余624项通过。关闭构建和隔离服务后，最终 `pnpm test --maxWorkers=1 --reporter=dot`：98 文件、627 测试全部通过（169.31秒），未放宽断言或超时门槛。
- `pnpm typecheck` 已通过；最终构建包含完整类型检查，未关闭 TypeScript 验证。

## 浏览器证据

使用现有本地集成器：3900 应用、3901 公开入口、3902 后台、3903 模拟 Shopify。新建独立系统临时目录、虚构管理员和模拟 API，未读取生产账号密码或调用真实远端。

1. 登录后创建 Maya：不填社媒主页，以10%佣金保存成功，生成 `/r/maya`。
2. 合作结束日等于开始日时拒绝保存，显示“合作结束日：合作结束日须晚于开始日”；手机上自动聚焦错误（role=alert），提示位于视口顶部，其他输入仍在。
3. 改名为“Maya 更新”、目的地改首页：保存后别名仍为 `maya`；详情的社媒显示“未填写”。
4. 再创建 Maya，0%佣金且主页留空：成功生成不同的 `maya-` 后缀别名。
5. 从公开入口实际打开原 `/r/maya`：抵达首页，后台原合作访问/到站更新为1/1。
6. 桌面1440×900、手机375×812截图复审；另核对360×800、768×1024、1920×1080。各尺寸文档宽度等于视口，弹窗 scrollWidth=clientWidth，无横向溢出。Esc 关闭弹窗并将焦点返回“新增合作”。

测试结束后已停止集成器，删除本轮创建的独立临时目录及全部测试数据（两个合作、三个条款版本、一条访问链路），3900–3903 无测试服务残留；恢复浏览器视口并关闭本轮测试标签。日常本地库、用户已有截图及生产环境未修改。

## 发布边界

本次只需更新管理后台镜像和 worker，现有主站读取的别名、条款和归因表保持兼容。生产仍需在代码提交推送后拉取并运行 `bash deploy/update-admin.sh`。本地验收不等于已发布到服务器。
