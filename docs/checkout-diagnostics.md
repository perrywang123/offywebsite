# 匿名结账诊断

2026-11-01：已实现并完成本地隔离验证；不等同生产部署或真实支付验收。本次仅增加记录与管理查看，国家选择器、市场优先级和购买拦截规则未改造。

## 管理员怎么用

登录现有独立端口后台，打开“结账诊断”（`/admin/checkouts`）。按记录编号、商品名/handle、国家、准备结果及日期筛选，每页 25 条。日期按北京时间，数据库时间为 UTC 毫秒。

点击“查看详情”，依次核对国家、商品、Shopify 结果和事件时间线。商品名、变体、数量、价格/币种来自本次服务端读取快照，不作为网站商品数据回退。Shopify 警告单独提示；有生成链接的记录也可能包含警告。国家依据会展示采用的头、其他国家代码线索、IP 判定来源或默认配置，定位线索不代表已由买家确认。

“查看完整链接与响应”通过服务端鉴权、Origin/CSRF 校验和管理员审计后解密；可复制原始链接交给 Shopify 支持排查，页面不会自动访问它。链接及购物车可能失效，生成时的 URL 也可能与 Shopify 后续跳转后的浏览器 URL 不同。

## 采集范围和结果语义

| 阶段              | 存储事实                                                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 购物袋点击结账    | 商品 code/数量、语言、发起页面路径、当次国家判定证据；随机单次编号和回执                                                                             |
| 浏览器前置验证    | 商品验证失败、请求超时/异常；浏览器报告单独标注                                                                                                      |
| 结账 API 收到请求 | 服务端国家判定、实际提交商品；无回执的直接 API 调用也登记                                                                                            |
| 服务端商品核对    | 解析出的商品名、变体、可售/报价状态、单价和币种、逐件拒绝原因                                                                                        |
| Shopify 请求      | 店铺/API 版本、国家/语言、变体与数量、脱敏 attributes；不存认证头                                                                                    |
| Shopify 响应      | HTTP 状态、请求编号（上游提供时）、耗时、实际购物车国家/行/数量/币种、warnings/userErrors/GraphQL errors；非 JSON 响应加密保存最多 4096 字符用于诊断 |
| 返回与跳转请求    | 服务端最终结果、生成的原始 checkout URL、浏览器请求导航的观察                                                                                        |

`started`=登记；`processing`=服务端接收；`client_failed`=尚未被服务端接收时浏览器报告失败；`failed`=服务端准备失败；`redirect_ready`=已生成链接。后到达的浏览器超时事件不能覆盖服务端结果。

记录计数是尝试次数，不是独立访客、订单或转化率。Offy 无法读取跨域 Shopify 页面的 Sold out 弹窗；这些记录不证明页面到达、支付成功或失败。Shop 原生购买不经过 Offy，不在此表采集；Shop 跳“访问商家网站”后在 Offy 结账则会记录。

从新版本部署后开始采集，不能还原历史用户。断网、请求未到服务器、存储故障或浏览器阻止请求时不能保证记录完整；诊断失败仅输出固定错误码，不阻止原购买流程。原有每次新建 Cart、原始链接跳转、KOL attributes 和归因保持。

## 数据和保留期限

- `checkout_attempts`、`checkout_attempt_events` 在现有 SQLite 数据库中；不写订单表或佣金账本，不依赖 KOL 开关采集。
- 普通记录和脱敏响应保留 30 天；完整链接、Cart 密钥和完整 Shopify 响应采用 AES-256-GCM 加密，保留 7 天。到期读取立即拒绝；每小时和有访问时执行清理。备份按运维自身的保留策略处理，不受在线清理自动删除。
- 不保存邮箱、详细地址、原始 IP、Cookie、认证头或稳定访客 ID；回执仅存 SHA-256，30 分钟有效且只可关联一次匹配的 checkout，不能读取记录或写服务端结果。每张回执最多记录 8 个浏览器观察。
- `KOL_ENABLED=false` 仍采集；管理查看沿用现有后台开关、可信入口、会话和生产邮箱白名单。公共网站拒绝所有管理路径，管理响应 private/no-store。

## 发布、密钥和恢复

主站采集和后台查看都需更新到对应版本。可以先执行 `bash deploy/update-storefront.sh --kol`，成功后再执行 `bash deploy/update-admin.sh`，分两次构建/发布；原整套入口 `bash deploy/update.sh --kol` 仍可用。只更新后台不会给旧版主站增加采集能力。新增表由启动迁移创建，继续使用原 `/data` 卷和主站/后台端口，不导入本地测试库。

`CHECKOUT_DIAGNOSTICS_KEY` 为可选的 64 位十六进制密钥，通过 `src/lib/env.ts` 校验。留空时，首次需要加密会在数据库同目录原子创建 `checkout-diagnostics.key`（0600）；主站/后台共用卷，自动读取同一文件，无需手填密钥。

独立/整套部署脚本的在线 SQLite 备份会同时复制已有的自动密钥，文件名是 `<数据库备份>.checkout-diagnostics.key`。恢复数据库时，将对应密钥恢复为数据库同目录的 `checkout-diagnostics.key`，保留 0600 权限和运行用户的读取权限。若显式配置环境密钥，应从私密配置备份恢复相同值。密钥丢失不能解密原文，脱敏记录仍可用；现有记录到期前不要直接轮换密钥。

## 隔离验证

启动 `pnpm kol:integration` 后，运行 `node scripts/checkout-diagnostics-integration.mjs`。工具只请求固定 loopback 模拟器，检查独立测试库前缀，不读取 `.env`，不访问真实 Shopify，不创建订单或付款。测试记录只存在临时数据库，不随 Git 或正常生产发布进入服务器。验证证据见 [验收记录](checkout-diagnostics-validation.md)。
