## 统计与边界

全局日期（Asia/Shanghai）、记录来源、广告/系列 ID 和测试排除统一作用于图表；统计全体匹配保留记录，而非每页30条明细。事件/发送状态/队列仅筛明细。趋势为事件时间的每日次数或浏览器去重，周期去重另算。前后窗口不完整时不伪造增长率。

概览独立统计各阶段；主漏斗仅按窗口内同浏览器的 PageView → ViewContent → CheckoutReady → 该次结账编号对应的付款历史订单顺序串联。加购为可选分支，允许 Buy Now。缺少前置事件不补造，跨来源组去重不可相加；不宣称 Meta 最终归因。

付款历史包含后续部分/全额退款、排除取消、默认排除测试；订单创建也必须在窗口内且不早于准备结账。未知配置、未完成/失败/超过45分钟的同步使付款格显示“—”，旧证据仍可查。金额和退款按币种另列，非净收入。CAPI 健康只统计 AddToCart 应发送任务，无任务不显示100%。

## 本地与自动化

先完成失败测试，再实现聚合/图表。覆盖跨日/周期去重、超过30条分页、重复结账/多订单、等时刻顺序、缺失/错误前序、Buy Now、来源变化、测试排除、退款/取消/未付款、范围外订单、空/未来日期、只读及标识不外泄。组件覆盖指标/单位切换、阶段/广告下钻、未知同步、CAPI 无任务、显式应用筛选和错误快照保留。

本地使用 `OFFY_TEST_META=true pnpm exec tsx scripts/kol-integration.ts`，4511/4512/4513 与临时 SQLite、模拟 Shopify/Meta 隔离；页面明确标注非真实 Meta。单独构造301条观察、16笔模拟订单，仅用于图表浏览器验收；不导入生产或镜像。

- 趋势指标/次数切换、广告来源统一筛选、阶段队列明细、分页、事件弹层及关联模拟订单均可用。
- 临时模拟订单同步失败时付款格变“—”且禁用阶段下钻，恢复状态后回到有效证据。
- 360/390/768/1440/1920px 页面 `scrollWidth` 等于视口宽度；宽表内部滚动，手机提示左右滑动，弹层能关闭并恢复焦点。
- 最终159个文件、966项测试全绿，类型检查和 ESLint 通过；本地生产构建与 GitHub CI 均通过。20,000条模拟记录（5,000个浏览器、20组来源）的本机只读聚合约67ms，这不是服务器性能承诺。
