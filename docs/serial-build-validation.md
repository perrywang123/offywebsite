# 串行构建检查与日志验收

变更：`2026-11-01-serial-build-checks`。本轮只验证本地代码和隔离目录，没有连接生产服务器或修改其配置、数据库，没有生产订单/付款操作。

## 实现

- Docker沿用 `RUN pnpm build`，该命令通过 `scripts/build.mjs` 先执行lint，成功后才执行 `next build --turbopack --no-lint`。没有配置 `typescript.ignoreBuildErrors`，Next.js内的类型检查保留。
- 构建器输出UTC时间、阶段开始/结果、耗时/退出码及每30秒进度。Linux cgroup内存是尽力读取的当前范围观察值，不是worker峰值；本机不可用时明确显示 `unavailable`。捕获到SIGINT/SIGTERM/SIGHUP时记录取消并将信号转发至阶段进程组。
- 部署自动保存Docker构建combined stdout/stderr与plain进度到原项目 `.deploy-logs/`；每次创建独立日志，最新引用为 `latest-build.log`。目录0700、实际日志0600。构建或日志输出失败均不进入DB备份/服务替换。
- 日志被Git、Docker上下文、源码归档/同步和格式化工具排除；check-only不创建日志。没有改变服务端口、CPU配额、共享卷、KOL配置或主站/后台独立发布范围。

## 边界与服务器操作

原42分钟记录表明编译完成后在检查阶段长时间等待并被取消，尚未证明是某一具体检查、OOM、终端断线或框架缺陷造成。本次减少lint/类型检查的并发并补全进度日志，不能声明已经复现或根治服务器上的长等待。

日志记录范围为Docker构建；构建前配置校验失败不会创建本次新记录，latest可能仍指向以前的构建。普通前台部署仍可能随终端退出而取消，自动保存日志不等于后台保活；不可捕获的终止可能留下部分日志。请按 [服务器tmux执行步骤](deployment.md#在服务器保留长任务与查看日志) 启动并恢复原任务。生产检查门槛保留，预构建镜像仍未接入。
