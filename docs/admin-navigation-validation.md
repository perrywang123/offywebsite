# 后台栏目切换验收

日期：2026-11-04。本地源码与隔离运行验证，没有发布生产，没有修改 Shopify、服务器凭据或数据库结构。

## 原因与实现

原侧栏使用普通 `<a>`，点击触发完整页面导航；控制台在叶页面内初始化，每次都要重新获取 `/api/admin/kol/state` 并展示整页“正在连接合作账簿”。

现改为 Next.js 站内链接，共享 `/admin/layout.tsx` 持有 `AdminWorkspace` 和持续挂载的控制台。叶页面仍验证合法地址，未知路径仍404。首次进入/手动整页刷新仍需要初始连接；正常栏目切换保留框架和最近读取的数据，只在刷新按钮显示“更新中…”。

切页后台刷新使用 AbortController 取消上个读取；即使旧响应稍后成功，也不允许恢复已失效的登录或覆盖新结果。瞬时刷新失败保留数据并显示“当前显示上次读取的数据”；401清空快照、筛选及临时弹窗，返回登录。没有把管理数据写入 localStorage/sessionStorage。

合作、优惠码、订单、月结的搜索/筛选按栏目保存；切换关闭临时弹窗。结账诊断继续使用自身 URL 筛选和内容区读取提示，侧栏不消失。每次管理 API 的服务端身份验证、共享布局可信入口校验、Origin/CSRF 及账务核验保持原规则。

- 针对性13项通过：包含框架节点保持、筛选独立、刷新失败保留旧数据、401回登录、迟到响应不可恢复失效登录、共享布局归属、未知路径，以及之前的合作表单和诊断交互。
- `pnpm typecheck` 通过。
- `pnpm build` 通过：先行 ESLint、Next.js 内置类型检查、standalone 输出完成，未跳过类型检查。
- 全量首次复跑：99文件中98文件通过，632项中631项通过；既有部署脚本 `leaves a configured Nginx target untouched...` 触发默认5秒超时。本次没有改动部署脚本或该断言，使用 `--testTimeout=15000` 为子进程集成测试提供等待预算。最终完整运行 `pnpm test --maxWorkers=1 --testTimeout=15000 --reporter=dot`：99文件、632项全部通过（158.07秒）。

## 实际浏览器

使用项目本地集成器和本轮新建的系统临时目录，3900应用、3901公开入口、3902管理入口、3903模拟 Shopify。虚构测试账号，不使用生产密码或真实令牌。

1. 登录后合作页搜索 `maya`，点击订单：侧栏及账号一直保留，直接显示订单区域和局部“更新中…”，订单搜索为空。
2. 订单搜索 `#1001`，切优惠码再用浏览器后退：订单搜索恢复 `#1001`；前进有效。返回合作页恢复 `maya`。
3. 连续点击五个栏目：均未重现整页连接态；结账诊断第一次局部显示“正在读取结账记录…”后正常读取空库。
4. 真实打开 `/admin/orders/unknown`：404，未渲染控制台。
5. 在独立测试库中将本轮测试 session 过期，再切栏目：真实 state API 返回401，页面回到登录，侧栏不再可见。没有修改生产账户或会话。
6. 1440×900 / 375×812截图检查；360×800、768×1024、1920×1080核对文档宽度等于视口，无横向溢出。

测试结束已停止集成器，清理本轮临时数据库、会话和日志，3900–3903无测试服务残留；关闭本轮测试标签，恢复视口。之前的表单修复、日常数据库、用户已有设计截图保留。
