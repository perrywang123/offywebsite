# 独立主站发布验收

日期：2026-11-01。本次只在本地仓库和隔离临时目录测试，没有连接生产服务器或修改其配置、数据库，没有生产订单或付款操作。

## 发布范围

- `bash deploy/update-storefront.sh --kol` 自动拉Git，只构建 `offy-app:local`，用app镜像执行原有SQLite在线备份，之后只替换app并检查3000健康。
- `bash deploy/update-admin.sh` 保留独立后台发布，只构建admin、替换admin与worker，验证已运行主站的共享配置及后台就绪/HTTPS。
- 首次KOL启用可先主站、成功后再后台分次执行；主站发布不要求后台已启动，不运行后台心跳检查或Nginx安装/重载。
- 原完整发布入口、内部认证复用、共享卷、3000/3001源站端口及1 CPU构建器保留。两个独立范围不能同时指定，Git重载后范围不丢失。
- 已运行后台的真实数据库卷/路径与店铺需要匹配。后台已启用KOL时，共用设置必须一致；旧后台未启用时允许主站先开启，但内部认证准备仍拒绝密钥冲突。

## 隔离测试证据

先新增测试并观察旧代码因缺少主站入口/范围和反向配置检查而失败，再实现并通过：

- Docker/HTTP命令替身捕获全链路调用：KOL开启或关闭时，主站独立发布都不构建、启动、停止或在admin/worker中执行检查，且备份先于app替换；不会通过关闭KOL获得隔离。
- 首次没有后台时先主站启用KOL，随后后台独立发布成功；私密配置文件字节内容保持原样。
- 真正运行中的后台数据库路径、卷、店铺或启用中的KOL密钥不匹配时，在构建/替换前停止，错误不输出配置值。
- 有明确Nginx目标但Nginx命令不可用的模拟环境下，主站发布仍成功，原代理文件保持原样，不请求后台HTTPS入口。
- 构建后模拟备份失败和app健康失败，得到非零退出且没有后台/worker补偿操作；健康失败不代表应用自动回滚。
- 真实本地bare Git upstream和第二checkout：自动拉到新脚本、重载时保留独立范围、显式KOL启用和配置文件绝对路径；拉取失败/本地tracked修改在构建前停止。主站与后台入口均通过同一组Git验证。
- 缺少Git checkout时独立发布拒绝陈旧源码；`--check`不拉代码、不创建构建器、不备份、不修改服务。
