# Design — Shopify 商业数据权威化

状态：2026-10-31 用户已确认并授权实现；生产发布不在本次范围。

## 数据边界

“所有数据以 Shopify 为准”在本变更中指商业事实：商品名、商品描述、商品图、价格、币种、可售状态、SKU、变体 ID、系列名称和成员。品牌故事、首页品牌主张、FAQ、联系信息、未来 IP 预告和站点设计资源保持现有内容管理方式。政策正文继续取 Shopify，取不到不编造正文。

本地系列 slug→Collection handle 映射是路由配置，可保留；不能再以本地名称/成员替代失败的 Collection 响应。移除本地 `featured`、区域 `badge`、翻译、尺寸等对商业事实的静默覆盖；保留哪些运营展示字段需逐项明确来源，不能沿用旧商品快照。

## 读取与错误模型

使用显式成功/失败结果，成功的空数组不得与失败合并。详情只有在 Shopify 成功响应且明确返回 null 时才能按不存在处理。非 2xx、GraphQL 错误、超时、凭据缺失和必需商业字段缺失应进入不可用状态，不能转成本地商品、USD 0 或 404。

产品关键读取和结算验证使用 `cache: no-store`，并在同一请求内去重；公开商品 API 返回 `Cache-Control: no-store`。移除以 60s revalidate 在失败时继续使用旧商业数据的路径。页面现有 ISR、metadata、sitemap 均需纳入验证，不能只改 fetch 后宣称已消除旧价。购物袋打开、页面恢复可见及结算前重新确认商品；任何浏览器快照都不参与计价。

区域限定探测是另一条路径：探测不完整时隐藏限定推断，不凭部分失败推导“仅某国可售”。区域探测不保留跨请求缓存，全部配置国家成功后才推断。

## 四种主要失败展示

1. 列表/系列：保留站点外壳，展示完整错误态，不显示骨架商品、旧价、虚构数量或假售罄。
2. 详情：显示通用说明，不显示未经确认的名字、图片或价格；保留重试、All Looks、联系入口。
3. 购物袋：保留本地行数据，明确告知已保存；暂不展示未验证行的商业事实和小计，不提供 Checkout。
4. 首页：保留品牌段落；产品资讯卡、New Looks、限定区和名册依赖验证。故障时合并为一处局部提示，不重复铺满错误面板。

正常空列表、确认 404 和售罄保持独立语义。单个推荐区失败不应把已经成功取得的详情隐藏；局部失败必须限定在对应模块，不能形成混币小计或用不完整列表当全量。

## 结算与 SEO

- Shopify/Stripe/PayPal 三条 provider 都不得在取数失败后使用本地商品计价或创建订单。
- 商品 API 不可用返回 503，可带 `Retry-After`；确认不存在才是 404。
- HTML 故障态不输出商品 Offer、虚构库存和商品数量，设置 noindex；首版可采用动态 200 + noindex（App Router 普通页面不能直接设置 503），若实现 HTML 503 需验证真实响应，不能只在文档承诺。
- sitemap 生成失败不能偷偷列出本地商品，也不能以不完整的成功空目录覆盖完整站点地图；sitemap.xml使用RouteHandler明确返回503+no-store，并以测试和HTTP响应验证。

## 性能取舍

商业数据从60秒缓存改为请求级新鲜读取会增加Shopify请求量和首屏等待。实现时用同请求去重与并发控制降低成本，并验证首页/metadata/购物袋重复读取；不以静默旧价换取表面可用性。并发规模、超时和重试节奏需测量，不承诺未经实测的延迟。

## 实现细节

列表、详情与结算统一首variant价格与可售状态，不用另一个规格的最低价。商业连接每页250并跟随游标，缺pageInfo、重复游标或后续页失败拒绝整个读取；商品归属最多250个Collection，超过即不可用，避免误归为merch。品牌化重试使用共享CommerceUnavailable，抽屉有Tab圈闭/焦点恢复，购物袋/结算页始终noindex。
