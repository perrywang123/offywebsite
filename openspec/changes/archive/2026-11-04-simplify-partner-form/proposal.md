# Why

新增合作把达人推广别名与落地页当成两个可自由填写的路径，管理员将 `/maya` 填入落地路径后被服务端拒绝，但页面丢弃字段错误，只显示泛化提示。社媒主页当前强制填写，也不符合运营需求。

# What Changes

- 表单仅填写 KOL 名称，服务端生成唯一、创建后固定的推广别名；同名合作和非拉丁名称也能生成链接。编辑名称保留已有别名和历史归因，旧 API 显式别名兼容。
- 社媒主页为空/缺省时允许保存；填写时仍要求有效 HTTPS URL。
- 将落地页改为首页/全部商品选择，显示它与系统生成 `/r/<alias>` 的区别；历史合法商品/系列目标在编辑时保留。
- 服务端返回中文字段校验信息，前端展示具体原因，日期错误明确指向结束日期。

# Capabilities

MODIFIED: `kol-platform` 的 Versioned KOL cooperation。

# Impact

影响 `src/server/kol/core.ts`、管理表单及其现有 API 错误展示、相邻测试和运营文档。沿用 SQLite 表及不可变别名约束，无迁移；独立站购物与 Shopify 调用不变。使用隔离数据库验证真实登录/新增/编辑/推广跳转，不写生产数据。
