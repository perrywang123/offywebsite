# Decisions

## 页面初始化与顺序

两秒容差只允许同一浏览器、同一路径的 ViewContent 略早于首个 PageView。付款仍须精确匹配 CheckoutReady 的 attempt ID、日期和订单时间；不对缺失事件、跨页面倒序或付款时间放宽。新客户端捕获当前已许可路由参数后再发布视图，避免读取已变动的全局 URL。

## 来源

无有效新标签时沿用最后一组有效标签。新有效标签完整替换，不能混用旧 campaign/ad 字段。fbc 始终采用真实新点击及原捕获时间，最后有效 UTM 不声称与后来的未知点击存在官方映射。仅 `utm_source=meta` 且 `utm_medium=paid_social` 时，缺失的 ID 才可由纯数字 utm_campaign/content/term 推导；显式 ID 优先。读侧 SQL 与 JS 使用相同规则，保留原始存储不改写。

未允许营销时不创建身份、持久来源、排队或回放事件。晚到许可之前已离开的带参页面仍可能无法归因；本轮不把这个客观边界“补造”为已解决。

## 浏览器入队重试

固定同源 `/api/meta/events`，最多保留 50 条内存任务、并发 2 个、每条最多 3 次尝试、最长 60 秒。只对网络异常、超时、429、5xx 重试；其余 4xx 结束。重试使用同一已校验请求体/event ID/时间。撤回、禁用、身份改变或过期时取消任务并中止当前请求；不持久化浏览器 outbox，不等待它完成结账。

## 内测隔离

`utm_source=offy_validation` 或 `utm_medium=internal_test`（不区分大小写）是本地诊断来源。浏览器不加载/调用 Pixel；已载入的 Pixel 在进入该来源时撤回发送许可，离开内测且具备许可后可恢复。服务器独立抑制内测 AddToCart，防旧客户端继续污染正式数据。旧未发送任务置 suppressed，清除载荷；已成功发送的历史事实不改写。

## 验证

先失败测试，再最小实现；涵盖 1ms/2s 边界、跨路径/缺失/真正倒序、来源替换/数字 UTM/显式优先、HTTP/网络重试幂等、取消和容量、内测首屏及旧任务。全量测试、类型、lint、构建以及本地 Shopify/Meta stub 浏览器链路验证。不创建真实订单或访问生产发送端点。
