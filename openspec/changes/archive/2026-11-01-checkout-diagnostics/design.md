# 结账诊断技术与界面设计

状态：用户于 2026-11-01 授权实施，先规划后实现和测试；仅诊断范围。

## 链路

共享购物袋 checkout hook 在验证商品前调用登记端点，获得随机记录编号与短期高熵回执。回执只允许关联结账及追加少量客户端观察，不提供读取权限。服务器直接收到结账 API 请求时，无回执则新建记录，有有效且匹配商品的回执则单次关联。重复/伪造回执不覆写原记录。

国家解析返回 country/source/header/candidates/ipSource/default，pickCountry 继续返回同样字符串。保留国家头的有界代码证据，不保存原始 IP、Cookie、邮箱、地址或身份令牌。商品字段来自服务端实时 Shopify 读取，标注为本次尝试快照，绝不用作前台商品回退。

Shopify client 额外查询实际 Cart 的国家、行、数量、币种以及 warnings，记录原始结果但不增加购买拦截。客户端验证失败、网络超时与跳转请求单独标记为客户端观察，不能覆盖服务端结果。已生成链接不是 Shopify 页面已加载，更不是付款成功。

## 持久化与敏感数据

checkout_attempts 保存编号、时间、来源、商品输入、国家证据、服务端状态、错误/耗时及脱敏结果；checkout_attempt_events 保存有序阶段。正常应用与后台直接共用 getDb，不受 KOL 账务 shop guard 约束。失败捕获只输出固定错误码，诊断故障不阻断原下单。

AES-256-GCM 加密完整 Shopify 响应/原始 checkout URL/完整 Cart ID。CHECKOUT_DIAGNOSTICS_KEY 可选，默认为数据库同目录 checkout-diagnostics.key（独占创建、0600，两个容器共用卷）。数据库备份必须同时备份密钥；轮换需保留旧密钥至敏感记录过期。元数据 30 天，密文 7 天；读取始终执行到期限制，进程定时及访问时清理，不依赖 KOL worker。

## 后台设计契约

继承根 DESIGN.md 和现有 admin.css。目标：管理员先识别失败阶段，再查看国家、商品和 Shopify 证据。黑白灰为主体，绿/褐/红只承载带文字的状态。系统 sans，代码用 monospace，4/8/12/16/24/32 间距，44px 操作区。

第五项导航“结账诊断”。顶部说明统计边界和保留期；筛选含编号/商品、国家、服务端状态及日期，分页保留筛选。桌面表格突出时间/商品/国家来源/结果；手机转可读条目。详情使用可关闭、Esc/焦点返回的对话框，展示事件时间线、请求与返回商品、国家证据、HTTP/请求编号、脱敏 JSON。完整链接显式操作后经服务器审计解密，提供只读文本和复制，不自动打开或再创建购物车。

无装饰图表、虚构转化率和支付成功统计。加载、空白、查询失败、敏感数据过期/密钥不可用均有明确状态。360/768/1440/1920、键盘和 reduced-motion 验收。
